# 项目记忆

## 2026-08-10 - 立项

- 问题：Codex 依赖 CC Switch 的 `127.0.0.1:15721`；退出 CC Switch 会中断请求。
- 证据：早期上游 Responses 直连曾出现 HTTP 503，桌面切换工具的熔断并非纯界面误判。
- 决策：设计独立、本机常驻、仅服务 Codex Responses 的故障转移代理；key 保持在既有 `key.txt`，不记录或展示。
- 经验：HTTP 200 的 SSE 流仍可能承载 `response.failed`，必须在提交下游前检查初始事件。

## 2026-08-10 - 本地域名与进程策略

- 决策：公开版本统一使用本机回环地址的 `15722` 端口，不依赖自定义 hosts 记录，也不绑定特权端口 80。
- 失败方案：CC Switch 使用 KeepAlive 会在退出后反复激活窗口并抢占焦点，已停用。
- 最终方案：新代理使用无窗口 Background LaunchAgent，仅异常退出时重启。

## 2026-08-10 - 首次迁移

- 结果：本机 LaunchAgent 已运行，客户端 `fox.base_url` 已从 `15721` 切换到 `127.0.0.1:15722/v1`。
- 保留：未修改 `state_5.sqlite`、会话 JSONL、项目目录或认证文件；切换后当前会话继续工作。
- 回滚点：`runtime/backups/config.toml.20260810-102805-before-proxy-switch`。
- 公开化调整：取消自定义 hosts 依赖，默认回环地址可直接使用。

## 2026-08-10 - 可观测性

- 新增：当前 Provider 行高亮并标记“使用中”；最近 100 条事件在页面展示，磁盘最多保留 200 条。
- 事件字段：时间、Provider、成功/失败、耗时、脱敏信息。
- 隐私：事件日志不记录提示词、响应正文或密钥。

## 2026-08-10 - 动态 Provider 管理

- 问题：原实现把五个 Provider 写死，且从另一个项目的混合 `key.txt` 读取，无法在管理页安全增删改。
- 尝试：直接改原混合文件会影响无关凭据，因此未采用。
- 最终方案：只迁移五条 `codex-app-*` 到本项目已忽略的 `key.txt`；增加本机 API 与弹窗完成添加、改名、换 key 和删除。
- 安全约束：key 文件权限固定为 `600`；编辑不回显旧 key，空值表示保持；状态、事件、日志和 `dist` 均不含 key。
- 经验：删除后的动态列表必须以持久化配置和当前 key 文件为准，不能在重启时重新注入历史硬编码默认项。

## 2026-08-10 - 启动与安装韧性

- 问题：LaunchAgent 自动拉起与 `bootstrap` 可能发生竞态，出现服务已运行但安装脚本报错；固定操作列也导致中文按钮换行。
- 最终方案：安装流程轮询卸载和健康状态，校验服务身份及有效渠道；失败自动恢复上一份 `dist` 和 plist。增加 `doctor` 自检与 `repair` 修复入口。
- 容错：持久化数字字段损坏时回退默认值，不因单个错误字段阻止服务启动；key 和状态继续原子写入；无窗口 LaunchAgent 始终保活。
- UI：Provider 列宽按内容自适应，操作按钮禁止换行，并保留窄屏布局降级。

## 2026-08-10 - 品牌与中英双语

- 决策：最终产品名采用 `Switch Local Proxy`，计划 GitHub 仓库名为 `switch-local-proxy`；2026-08-10 通过 GitHub Search API 检查时完全同名结果为 0。名称不绑定 Codex、Claude 或具体模型厂商。
- 语言：支持 `English` 与 `简体中文`；跟随系统时中文系统显示简体中文，其他系统回退英文，手动选择持久化并覆盖系统判断。
- 翻译：使用授权的 Tongyi Qwen / DashScope 生成 67 项英文基线，随后按运维界面语境校正文案；新增请求成功文案后共 68 项。
- 验证：构建必须比较中英 key 集与占位符，并保持 `Switch Local Proxy`、`English`、`简体中文` 等固定名称。
- 发布边界：当前只完成本地命名和 GitHub 发布准备，不创建、不推送远程仓库；发布前必须重新检查名称占用。

## 2026-08-10 - 请求记录分页

- 问题：最近请求记录持续增长后难以浏览，也无法控制单页密度。
- 最终方案：状态接口返回保留的最近 200 条脱敏事件；前端提供 10/20/50/100 条分页大小、页码摘要和前后翻页。
- 持久化：每页数量保存在浏览器 `switchLocalProxy.eventPageSize`，当前页只属于本次页面会话。
- 隐私：分页只处理现有事件元数据，仍不记录或传输提示词、响应正文和密钥。

## 2026-08-10 - 模型与密钥可观测性

- 问题：Provider 名称不能证明请求使用的是 `sol` 还是 `luna`，编辑渠道时也无法核对当前 key。
- 最终方案：覆盖上游模型前保存客户端模型；事件记录 `requested_model` 和实际 `model`。状态接口新增固定格式 `key_hint`，队列和编辑弹窗复用同一摘要。
- 安全边界：完整 key 仍只在服务端按请求读取，浏览器、状态文件、事件文件、日志和 `dist` 不保存完整密钥；空密钥编辑仍保持原值。

## 2026-08-10 - 上下文能力被动观测

- 证据：供应商记录显示 P3 成功处理 364,127 输入 token、P5 成功处理 349,395、P4 成功处理 325,945；不能据此认定 P3/P4 有较低固定窗口。
- 决策：不执行每日主动超长探测；从真实请求开始记录 request ID、输入 token 估算、上下文错误样本和每条线路最大成功长度。
- 结果：状态与请求历史新增观测字段，未来可基于同一故障转移链判断线路异常，而不把单次上下文问题直接当成永久容量上限。

## 2026-08-10 - 502 同 Key 短重试

- 问题：供应商确认部分 502 与会话上下文或瞬时上游链路有关；立即切 Key 会增加线路切换，并可能降低供应商侧缓存命中。
- 决策：首次 HTTP 502 不立即熔断，等待 1 秒后在同一 Key 重试 1 次；仍失败才记一次失败、冷却并切换。其他故障保持原逻辑。
- 验证：端到端测试模拟首次 502、第二次 200，确认共请求同一上游两次、最终成功、失败计数为 0、事件 `retry_count=1`。
- 取舍：不做无限或多次重试，避免上下文确定性错误带来额外等待和重复计费；SSE 已输出有效内容后仍禁止重试。
- 修正：输入 token 估算跳过内嵌图片和文件的 base64 正文，防止附件体积被误当成文本上下文。
- 迁移：估算器版本升级时清空旧算法生成的约 145 万 token 最大值，从新请求重新累计；其他运行统计和配置保持不变。
- 兼容：旧事件保留成功/失败等证据，但因没有估算器版本，页面将其输入估算显示为 `-`，不与新样本混用。
