# Switch Local Proxy - 功能需求

**版本：** v0.4
**日期：** 2026-08-10
**变更原因：** CC Switch 关闭会使 Codex 的本地代理失联；其多 key 熔断状态对当前场景不够直观、难以人工控制。
**变更 AI：** Codex

## 1. 背景与问题

Codex 当前通过 `127.0.0.1:15721` 访问 CC Switch。本机关闭 CC Switch 后，本地端口消失，Codex 无法继续请求。

已验证 P1-P4 在 2026-08-10 的直接探测中均返回上游 HTTP 503；这不是单纯的界面熔断误判。现有方案仍存在两个体验问题：

- 无法快速看清每个 key 为什么被排除、还需等待多久恢复。
- 代理生命周期绑定桌面应用，退出应用会中断 Codex。

## 2. 产品目标

建立一个仅供本机使用、独立于桌面切换工具的 AI API 代理。首个适配器接收 OpenAI Responses 兼容请求，可按优先级在多个上游 key 间自动故障转移，并通过本地管理页观察与调整状态；后续可增加 Anthropic 等协议适配器。

## 3. 非目标

- 不绕过上游服务真实的 502、503、限流或容量限制。
- 不改变或模拟模型能力；对上游统一请求 `gpt-5.6-sol`。
- 不做多用户、远程访问、账号共享、云端同步或公网暴露。
- 当前版本不宣称已经兼容 Anthropic Messages、Gemini 等不同协议；这些能力需要独立适配器。

## 4. 使用者与场景

唯一使用者为本机用户。主要场景：

1. Codex 发起 Responses 请求，代理优先使用成本最低的可用 key。
2. 某个 key 返回 502 时，先等待约 1 秒并用同一 key 重试 1 次；仍失败才冷却并尝试下一 key。503、超时或 HTTP 200 后 SSE 流内返回容量/失败事件仍直接尝试下一 key。
3. 失败 key 被临时冷却，后续请求不再浪费时间请求它；冷却结束后自动允许一次探测。
4. 用户在浏览器打开本地管理页，查看当前使用 key、冷却倒计时、最近失败原因并手动调整。

## 5. 核心功能

### 5.0 产品名称与语言

- 产品名：`Switch Local Proxy`；计划发布的 GitHub 仓库名：`switch-local-proxy`。
- GitHub 英文描述：`A local AI API proxy with prioritized key routing, automatic failover, retries, cooldowns, and real-time provider monitoring.`
- 许可证：`The Unlicense`，允许任何人复制、修改、发布、使用、编译、销售和再分发，包括商业用途，不要求署名或采用相同许可证。
- 支持 `English` 与 `简体中文`，语言选项始终使用各自原生名称。
- 初始为跟随系统：系统语言列表包含中文时使用简体中文，否则回退英文。
- 用户手动选择后保存在浏览器本地存储中，并优先于后续系统语言检测。

### 5.1 本地代理接口

- 仅监听 `127.0.0.1`，默认端口 `15722`。
- 对 Codex 提供 OpenAI Responses 兼容接口：`/v1/responses`。
- 转发必要的请求头与请求体，不记录请求正文或模型输出。
- 无论客户端请求中携带何种模型名，向本机配置的上游统一传递所设定的模型名。
- 支持非流式 JSON 与流式 SSE。

### 5.2 Provider 队列

初始队列由本机 `key.txt` 中配置的 Provider 建立：

| 优先级 | 名称 | 定位 |
| --- | --- | --- |
| P1 | 用户配置的 Provider | 最低成本优先 |
| P2 | 用户配置的 Provider | 次优先 |
| P3 | 用户配置的 Provider | 平衡选项 |
| P4 | 用户配置的 Provider | 次高优先级 |
| P5 | 用户配置的 Provider | 最终兜底 |

- 管理页可调整优先级、启用/停用某项。
- 管理页可添加、修改和删除 Provider。添加时名称和密钥必填；修改时密钥留空表示保持原值；删除需二次确认。
- 管理页只显示名称、状态、错误摘要、延迟和冷却时间，以及 `前6位…后4位` 的 key 脱敏摘要，绝不显示完整 key。
- 编辑 Provider 时显示同一脱敏摘要；密钥输入框为空表示保留现有密钥，脱敏摘要不会被当作新密钥写回。

### 5.3 故障转移与冷却

- 默认阈值：502 允许同一 key 额外重试 1 次，第二次仍失败才触发冷却；其他可重试故障单次即触发冷却。
- 默认冷却：5 分钟，可在管理页改为 1-60 分钟。
- 可判定失败：HTTP 429、5xx、连接失败、连接/首包超时、Responses JSON 失败对象、SSE 初始阶段的 `error` 或 `response.failed`。
- 同一个请求中按优先级尝试所有未冷却且启用的 key；成功后立刻停止尝试。
- 同 key 的首次 502 不增加失败计数、不写失败事件；最终事件记录本次同 key 重试次数。
- SSE 已产生有效内容后发生的异常，不能安全重试，以免重复或截断内容；代理只记录错误。
- 若全部 key 不可用，返回明确的 503 JSON，包含各项的脱敏失败摘要和下一次最早可重试时间。

### 5.4 状态与管理页

管理页默认只通过本机回环地址的 `15722` 端口访问，不依赖自定义 hosts 记录。

- 顶部显示：服务运行状态、当前可用数量、当前选中/最后成功的 key、最近一次切换。
- Provider 列表显示：优先级、启用状态、健康/冷却/探测中、冷却倒计时、最后成功时间、最后错误和最近延迟。
- 当前正在尝试或最近成功的 Provider 在列表中高亮并显示“使用中”。
- 最近请求记录显示时间、Provider、客户端请求模型、实际发送给上游的模型、成功/失败、耗时和脱敏信息，最多保留 200 条；模型不一致时显示 `请求模型 → 上游模型`，不保存提示词、响应正文或 key。
- 请求记录支持分页，用户可选择每页 10、20、50 或 100 条；每页数量保存在浏览器本地，刷新后继续使用。
- 操作：添加、编辑、删除 Provider，上下移动优先级、开关 key、单项恢复、全部恢复、修改冷却分钟数。
- 实时刷新：每 3 秒轮询本机状态接口。
- 所有改动即时保存到本机状态文件，应用重启后保留。

### 5.5 常驻与恢复

- 服务用 macOS `LaunchAgent` 常驻；登录时启动，异常退出时自动重启。
- CC Switch 是否运行不影响服务。
- 提供 `run.sh start|stop|status|verify|install` 作为人工维护入口。
- 服务健康接口为 `/api/health`，仅本机可访问。

## 6. 配置与密钥安全

- 密钥只保存在本项目已忽略的 `key.txt`，文件权限为 `600`；不上传、不写入状态或日志。
- 所有运行状态保存在项目内已忽略的 `runtime/`，状态文件不含 key。
- 管理页允许提交新 key，但不支持显示或导出完整 key；编辑时服务端只在收到非空新值时替换旧 key。
- 首次迁移工具仅从原混合配置文件提取 `codex-app-*` 行，不修改原文件，也不输出密钥内容。
- 日志只写 provider 名、HTTP 状态、耗时和脱敏错误类型。

## 7. 迁移方案

1. 启动并验证独立代理后，将客户端 base URL 改为本机 `15722` 端口下的 `/v1`。
2. 用一次最小 Responses 请求验证本地接口、模型强制覆盖和回包。
3. 保留 CC Switch 安装与配置，不删除其数据库；它不再是 Codex 的运行依赖。
4. 若需回滚，仅将 `base_url` 改回 `http://127.0.0.1:15721/v1`。

## 8. 验收标准

- CC Switch 退出后，Codex 仍能通过 `15722` 成功请求。
- 任意可用 key 成功时，客户端收到正常 Responses/SSE 响应。
- 模拟或真实触发某 key 的 5xx 后，该 key 在管理页显示 5 分钟冷却，当前请求尝试后续 key。
- 模拟上游首次 502、第二次成功时，当前请求成功返回，Provider 失败计数不增加，请求记录显示“同 Key 重试 1 次”。
- 冷却到期后的下一请求会重新尝试该 key；失败则重新冷却，成功则恢复正常。
- 管理页能调整队列、开关 provider 和手动恢复，重启服务后配置仍存在。
- 管理页能添加、改名、换 key 和删除 provider；新增项默认排在队尾，删除后不会在重启时恢复。
- 管理页、日志、Git 文件及命令输出均不含完整 key。
- Provider 状态只返回 `key_hint`（前6位和后4位），并累计历史最大成功输入与上下文错误样本；事件记录同时保存 `requested_model`、`model`、请求 ID 和输入 token 估算，旧事件缺少这些字段时显示兼容默认值。
- 英文和简体中文语言资源 key、占位符完全一致；切换语言不影响 Provider 状态和请求记录。
